# AI 接入研究：AI 敌人、AI 队友与 AI 托管

Status: 研究稿（只做分析与方案，不改运行代码）
Date: 2026-11-23

> 本文保留 2026-11-23 早期研究时点的代码分析与分阶段建议。随后已实现单架本地僚机、暂停设置、友军标记和可选大模型高层指令，当前行为见[实现笔记](../../../.agents/notes/implemented/feature/2026-11-23-wingman-ai-link.md)与[验收记录](../../../sky-patrol/VERIFICATION.md)。下文“队友不存在”和第 8 节问题对应研究时点；更完整的敌机战术、通用 Pilot 与玩家托管仍待后续设计。

## 0. 结论先行

- **AI 敌人**已有可用的 FSM + 转向骨架，但只有 `patrol / engage / flee` 三态，没有兵种战术、编队协同、导弹规避和目标选择。升级重点不是“更快的飞机”，而是**决策层与公平性参数**。
- **AI 队友**在代码里完全不存在：`G` 只有 `enemies`，锁定与碰撞也只认 `enemies + ground`。队友必须作为独立阵营实体加入，不能塞进 `G.enemies`。
- **AI 托管**已有原型：`simulate()` 里的测试 bot 已经在飞玩家的飞机、开火、打干扰弹（`src/60_main.js:588-616`）。它是最现实的起点，但目前绑定俯视鼠标坐标、使用 `Math.random`、没有安全边界与接管协议。
- 推荐统一为**四层 AI Pilot**：感知 → 决策（轻量行为树 + 效用评分）→ 转向意图 → 控制适配。敌人、队友、托管共用同一套意图接口，控制适配层分别写进敌机状态或玩家的 `readSteering` 输入结构。
- **不引入第三方 AI 库**。项目是零依赖、单文件 IIFE 构建，复杂度用约 150–250 行自研运行时即可覆盖。
- **公平性红线**：现有 `43_defense.js` 已把敌机速度/转弯半径锁定到玩家参数。AI 升级不得绕过这条约束；难度应来自反应延迟、瞄准误差、决策频率和协同，而不是数值作弊。

## 1. 现状：代码事实

### 1.1 全局状态

`src/40_game.js:28-61` 的 `G` 是唯一世界状态：

```js
enemies: [], ground: [], missiles: [], bullets: [], ...
player: null,
testInput: null,
threatList: [],
```

没有 `allies`，没有 `pilot`，没有阵营字段。所有可锁定目标由 `collectTargets()` 返回，只包含 `G.enemies` 与 `G.ground`（`src/42_combat.js:120-125`）。

### 1.2 敌机生成

`spawnDrone()`（`src/42_combat.js:86-117`）构造敌机实体：

- 位置：玩家前方 1080–1650 m（防御关）或 1250–2300 m（旧模式）
- 状态字段：`kind / hp / energy / aware / state / missileCd / gunCd / los / anchor / orbit / turnRadiusFactor`
- 防御关由 `DEFENSE_AIRCRAFT` 提供数值（`src/43_defense.js:3-9`）：drone / fighter / transport 三类

### 1.3 敌机决策与运动

`updateEnemies()`（`src/42_combat.js:629-781`）每帧对每架敌机：

1. **侦测**：`enemyDetectsPlayer()`（583-598），距离 + 1.35 rad 前锥 + 0.25 s 缓存的视线 + 太阳眩光随机失明。
2. **状态机**（651-662）：
   - `patrol`：绕 `anchor` 盘旋，能量恢复
   - `engage`：追玩家，能量消耗；能量 < 12 转 `flee`
   - `flee`：背向玩家逃 4.5 s，能量恢复
3. **期望点**（672-704）： patrol 取轨道点；engage 取玩家前置点（`lead`）；flee 取背离点；transport 走投放航线。
4. **转向**：`steerDrone()`（600-616），把期望点转成受限的 yaw/pitch 角速度，roll 只影响姿态。
5. **速度**：防御关用 `defenseTargetSpeed()`（`43_defense.js:24-31`），按玩家巡航速度的 52%–97% 取值。
6. **攻击**（750-763）：距离 < 2600 m、机头对准 > 0.55 时发射导弹；< 520 m 开机炮，带随机散布。
7. **分离**（765-773）：55 m 内互相推开。
8. **地形**：前方 280 m 高度检测抬升期望点，硬地板 48 m。

### 1.4 玩家飞行与输入

玩家控制已经被抽象成一个干净的输入结构：

```js
// src/40_game.js:373-415
readSteering() -> { sx, sy, burn, alt, turn, topView, mouseBlend }
```

`updateFlight()`（426-604）只消费这个结构，不关心输入来自键盘、鼠标、触屏还是测试。`G.testInput` 在 383-387 行直接覆盖输入，这是现成的注入点。

玩家可用的离散动作：`firePlayerGuns()`（`42_combat.js:249`）、`firePlayerMissile()`（349）、`tryFlares()`（`40_game.js:893`）、`triggerBarrelRoll()`（608）、`R` 回正（`p.recovery`）。

### 1.5 已有的“自动飞行”

- **标题画面**：`updateTitle()`（`40_game.js:797-829`）有一段地形跟随 + 缓慢 S 转弯的展示飞行，直接改 `p.yaw/pitch/pos`，不经过输入层。
- **测试 bot**：`simulate()`（`60_main.js:560` 起）里的 bot（588-616）会选最近目标、把目标投影到屏幕、移动鼠标坐标、按需加力、发射导弹、投放干扰弹、桶滚。它是**唯一接近 AI 托管的东西**，但：
  - 依赖俯视视角与屏幕坐标
  - 用 `Math.random()`，不确定
  - 没有地形避让以外的安全约束
  - 不处理玩家接管、暂停、弹药/燃油边界

### 1.6 现有平衡约束

`43_defense.js:11-41` 已经明确规定：

- 敌机速度 = 玩家当前巡航速度 × 兵种倍率（52%–97%）
- 敌机转弯半径 = 玩家当前转弯半径 × 1.45–2.2
- 玩家永远能切内圈

这条约束必须保留。任何 AI 战术层都不能直接改 `speed` 或 `turnRadius` 去“变强”。

## 2. 能力缺口

| 编号 | 缺口 | 影响 |
| --- | --- | --- |
| E1 | 三个兵种只有数值差异，没有战术差异 | drone/fighter 飞法一样，transport 只会走航线 |
| E2 | 除 transport 外不会规避导弹 | 玩家导弹几乎必中，战斗缺少反制 |
| E3 | 没有编队与目标分配 | 多架敌机挤在一起追同一点 |
| E4 | 没有目标选择 | 只有玩家一个目标，队友加入后无法区分 |
| E5 | 能量只是开关（>24 攻击、<12 逃） | 没有能量战、没有剪刀/盘旋 |
| E6 | 难度靠倍率，不靠反应与失误 | 高难度像“开挂”，低难度像“木桩” |
| E7 | 没有卡死检测与重规划 | 极端地形下可能长期贴地 |
| A1 | 没有队友实体、阵营、指令、HUD | 无法做僚机 |
| P1 | 托管只存在于测试 bot | 无法直接上线 |
| P2 | 没有玩家接管协议 | 托管与手动会打架 |
| P3 | 没有安全边界 | 可能撞地、打空、浪费弹 |

## 3. 三个方向的研究

### 3.1 决策模型选型

| 模型 | 优点 | 代价 | 适用 |
| --- | --- | --- | --- |
| FSM | 现有代码、便宜、可读 | 状态一多就爆炸；敌人 + 队友 + 托管会变成三套 FSM | 继续保留为“行为内部实现” |
| 行为树 | 结构清晰、可中断、可复用 | 需要运行时与调试面板 | **推荐做外层结构** |
| 效用评分 | 适合目标选择、速度模式、机动打分 | 权重需要调；容易抖动 | **推荐做叶子决策** |

**推荐混合**：外层用浅行为树决定“当前该做什么”（巡逻 / 交战 / 规避 / 撤退 / 归队），叶子用效用评分选目标、选速度、选机动。树保持 3–4 层，避免每帧全树重算。

不引入第三方库的原因：项目无 npm 依赖、构建是字符串拼接单文件；BT 运行时只需要 `Selector / Sequence / Condition / Action / Cooldown` 五种节点。

### 3.2 AI 敌人

**行为集**

| 行为 | 触发 | 动作 |
| --- | --- | --- |
| Patrol | 无接触 | 绕锚点/航线 |
| Intercept | 发现玩家，距离远 | 前置追踪，加速 |
| Pursue | 尾追或迎头 | lead pursuit，保持机炮包线 |
| Lag pursuit | 角度过大 | 放宽前置量，先恢复角度 |
| Break | 被咬尾 / 导弹逼近 | 大坡度转弯脱离视线 |
| Extend | 能量不足 | 直线拉开距离再恢复 |
| Defensive spiral | 被持续咬尾 | 螺旋下降，逼对方冲过头 |
| Missile defeat | `G.threatList` 出现来袭导弹 | 横切/俯冲/干扰弹（按兵种） |
| Rejoin | 与编队过远 | 回到长机后方槽位 |
| Strafe | 对地任务 | 对准地面目标一次通过 |

**感知层**（5–10 Hz，错峰）

- 接触列表：距离、方位角、进入角、接近率、视线
- 威胁列表：来袭导弹（玩家已有 `computeThreats()`，`40_game.js:848-871`，可泛化为任意阵营）
- 地形：前方 300 / 600 m 高度采样（现有 280 m 单点可扩展）
- 自身：能量、弹药、血量、编队槽位

**目标选择（效用）**

```
score(target) =
  weight.distance   * curve.distance
  * weight.angleOff * curve.angleOff
  * weight.threat   * curve.threatToSelfOrAlly
  * weight.value    * curve.targetValue
```

加 0.15 的“当前目标保持”奖励，避免每帧换目标。

**公平性参数**

- 反应延迟：0.2–0.8 s（按难度）
- 瞄准误差：机炮散布已存在（`42_combat.js:786`），可再加“追击时的前置量抖动”
- 决策间隔：0.2–0.5 s，不是每帧
- 导弹冷却与同时在空中数量：保持现有上限
- **不改** `defenseTargetSpeed` / `defenseTurnRadius`

**协同**

- 小队共享一个 `squadBlackboard`：长机、槽位、已分配目标
- 目标去重：同一目标最多 2 架，其余攻击次优目标
- 间距：现有 55 m 推开可保留，编队时改为槽位吸引 + 最小间距排斥
- 长机死后的接管顺序

**分兵种**

- drone：轻、慢、成群，打了就跑
- fighter：能量战，剪刀、盘旋、导弹规避
- transport：航线、投放、干扰弹，不主动缠斗

### 3.3 AI 队友

**数据模型**

```js
G.allies = []          // 新数组，不进入 G.enemies
entity.team = 'ally'   // 'player' | 'ally' | 'enemy'
```

锁定、碰撞、伤害、威胁检测都按 `team` 过滤。`collectTargets()` 需要改成“敌方阵营 + 地面敌方”，友军永远不可锁定。

**角色**

| 角色 | 行为 |
| --- | --- |
| Wingman | 跟随玩家后侧方槽位，玩家交战时分担火力 |
| Attacker | 攻击玩家当前锁定目标（指令） |
| Cover | 优先拦截来袭导弹/咬尾敌机 |
| Rejoin | 归队，回到槽位 |

**编队**

- 槽位定义在玩家 `basis` 下：右后 ±60 m、上 +20 m、后 -40 m（可配两机）
- 用 `arrive` 转向 + 弹簧阻尼，避免硬拉
- 与玩家、友机、敌机都做最小间距排斥
- 玩家大坡度/桶滚时槽位跟随 `renderBasis`，避免队友追着滚转疯转

**指令接口**

- 上下文指令：`攻击我的目标` / `掩护我` / `归队` / `自由开火`
- 键盘（如 `1/2/3/4`）+ 触屏按钮；HUD 显示当前指令与队友状态
- 指令只改高层意图，不直接改位置

**规则**

- 友军伤害：子弹/导弹命中前检查 `team`
- 弹药/燃油：队友有有限导弹与机炮，回补给时恢复
- 阵亡：坠毁/被击落，不复活（或波次补给复活，二选一）
- 不与玩家抢同一目标的锁定提示（HUD 区分）

**复用**

队友与敌人共用同一套 Pilot：感知、目标选择、转向、开火。差异只在“目标过滤”和“槽位/指令”两个装饰节点。

### 3.4 AI 托管

**两个层级**

| 层级 | 范围 | 适合 |
| --- | --- | --- |
| Assist | 自动回正、地形避让、失速/倒飞恢复、威胁时自动干扰弹 | 新手、受伤时 |
| Full | 自动导航 + 自动交战 + 自动投放 | 演示、挂机、测试 |

**控制契约**

托管不直接改 `p.pos/yaw`，而是输出与 `readSteering()` 相同的结构：

```js
{ sx, sy, burn, alt, turn }
```

再加离散动作调用：`firePlayerGuns()` / `firePlayerMissile()` / `tryFlares()` / `triggerBarrelRoll()`。

优先级：

```
玩家真实输入 > 托管输入 > G.testInput
```

建议新增 `G.pilotInput`，在 `readSteering()` 里按优先级合并；`G.testInput` 继续只服务测试，避免测试与托管互相污染。

**接管协议**

- 任意玩家输入（键盘/鼠标/触屏）立即暂停托管，0.2–0.3 s 防抖
- 暂停/失败/结算时托管自动退出
- 托管开启时 HUD 显示明确标识与当前模式
- 全托管不改变玩家的速度/转向设置，只按当前设置飞

**安全不变量**

- 离地高度 >= 180 m（现有敌机地板是 48 m，玩家要更保守）
- 无锁定不发射导弹；机炮只在射界内短点射
- 弹药/燃油耗尽自动脱离
- 不主动撞地、不主动撞友军
- 固定步进内确定性运行，使用 `rng()` 而不是 `Math.random()`

**原型改造**

把 `simulate()` 的 bot（`60_main.js:588-616`）抽成 `AIPilot`：

1. 去掉“把目标投影到屏幕再动鼠标”的俯视依赖，改成直接算期望航向/俯仰
2. 用 `rng()` 替换 `Math.random()`
3. 加地形避让、导弹威胁、弹药检查
4. 加模式状态机：`assist / navigate / engage / disengage`
5. 保留 `simulate()` 作为回归入口，改为调用新 Pilot

### 3.5 “AI 接入”的两种含义

如果“AI 接入”指**大模型驱动的智能体**，需要区分：

| 方式 | 适合 | 不适合 |
| --- | --- | --- |
| 确定性游戏 AI（本方案） | 帧级飞行、瞄准、规避、公平性、可测试 | 自然语言指挥 |
| LLM / Agent | 高层指令、无线电对话、任务生成、赛后复盘 | 60 FPS 飞控（延迟、非确定性、成本） |

推荐：**飞控与战术全部本地确定性 AI**；如果以后要接 LLM，只让它通过异步指令队列下发“攻击/掩护/撤退”这类高层意图，绝不进入逐帧控制回路。

## 4. 推荐架构

```text
Perception (5-10 Hz, 错峰)
  contacts / threats / terrain / self
        │
        ▼
Decision (BT + Utility)
  Patrol | Intercept | Engage | Evade | Extend | Rejoin
        │  intent { mode, target, slot, fireAuthorized, speedMode }
        ▼
Steering (每帧)
  desired point -> yaw/pitch/roll 受限指令
        │
        ▼
Control adapter
  敌人/队友 -> 写 e.yaw/pitch/roll + e.speed
  玩家托管 -> 写 G.pilotInput { sx, sy, burn, alt, turn } + 离散动作
        │
        ▼
现有 updateEnemies / updateFlight / 武器函数
```

**模块建议**

- 新文件 `src/44_ai.js`（构建顺序在 `43_defense.js` 之后、`50_ui_hud.js` 之前）
- 对外只暴露：`createPilot(entity, options)`、`tickPilot(pilot, dt)`、`pilotCommand(pilot, command)`
- 每个 pilot 一个 blackboard 对象，**构造时分配，运行时不分配**
- 决策 5–10 Hz，转向每帧；LOS 沿用 0.25 s 缓存
- 所有随机走 `rng()`，保证 `__PI.step()` 可复现

**实体字段建议**

```js
{
  team: 'enemy' | 'ally' | 'player',
  kind: 'drone' | 'fighter' | 'transport' | 'wingman',
  pilot: { blackboard, tree, cooldowns, currentIntent },
  formation: { leader, slot: {right, up, back} } | null,
  ammo: { missiles, gun },
}
```

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | 调试可视化：当前状态、目标、期望点、威胁、决策分数 | 可在浏览器里看到每架 AI 的意图 |
| P1 | 抽出 `AIPilot`，把现有敌机 FSM 原样迁入 | 全量 Node 292 项与现有浏览器验收不变 |

| P3 | 一架僚机：槽位、跟随、攻击我的目标、HUD | 编队误差、0 友伤、指令响应 |
| P4 | 托管 Assist → Full，接管协议与安全边界 | 手动接管 < 0.3 s，不撞地，不浪费弹 |

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| CPU/内存上升 | 决策限频、错峰、零分配、LOS 缓存；每帧只做转向 |
| 破坏确定性 | 禁用 `Math.random`，统一 `rng()`；固定步进 |
| 难度失衡 | 保留玩家参数锁定；难度只调反应/误差/协同 |
| 友军伤害与碰撞 | `team` 过滤；最小间距；友伤开关 |
| 托管让游戏失去意义 | 默认只提供 Assist；Full 需显式开启并显示标识 |
| 托管与玩家抢控制 | 输入优先级 + 任意手动输入立即接管 |
| 与测试耦合 | `G.testInput` 保持测试专用；托管走 `G.pilotInput` |
| 队友被锁定 | `collectTargets()` 只返回敌方；HUD 不画友军锁定框 |

## 7. 验收指标（建议）

- 敌人：10 分钟防守关无穿地、无卡死；转弯半径不低于玩家；机炮命中率 15%–35%（500 m）
- 队友：90% 时间编队误差 < 40 m；0 次友伤/碰撞；指令响应 < 1 s
- 托管：Assist 模式下 10 分钟不撞地；手动接管 < 0.3 s；Full 模式能完成第 1 关
- 性能：5 架敌机 + 1 架队友时，AI 决策开销 < 0.5 ms/帧
